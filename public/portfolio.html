WORK PROJECT / CREATED AND INTEGRATED

Address Normalization

Parsing, reference matching and review-ready output

Address records arrive with inconsistent abbreviations, incomplete components and conflicting regional information. They need a repeatable preparation process before matching and downstream use.

What I built

Created and integrated an address-processing engine that parses region, locality, street and building components; applies configurable normalization rules; and matches records against reference data. SQLite lookups and bounded caches support reference access.

Raw addressesParse + normalizeReference matchExcel + review flags

Deliverable

An Excel output with normalized fields, matching methods and data-quality flags. Uncertain or conflicting records remain identifiable for review.

Python / pandas / SQLite / YAML / Excel

Six focused local checks passed on the reviewed copy: five regression tests plus a SQLite integration-boundary test. They cover missing reference data, regional conflicts, village/building parsing, Excel output, lookup ambiguity and read-only reference access.

Checks use synthetic inputs. They do not establish production-wide matching accuracy or throughput. Client datasets and internal configuration are not included.

WORK PROJECT / CREATED AND INTEGRATED

Supplier Report Processing

Configurable ETL for recurring imports and 1C workflows

Supplier reports differ in headers, layout, data types and nested row groups. Recurring imports require consistent fields, quality checks and a controlled handoff to downstream systems.

What I built

Created and integrated a configurable ETL pipeline that maps supplier fields through YAML rules, converts values, preserves hierarchy boundaries, fills registry metadata and generates template-based Excel output. SQL Server registry reads and JSON status commands connect the stages to a 1C workflow.

Supplier ExcelMap + validateTemplate output1C status handoff

Deliverable

Standardized Excel files for downstream imports, required-field checks and staged JSON status messages. Supplier-specific rules are separated from the reusable processing logic.

Python / pandas / YAML / SQL Server / Excel / JSON

Verification and scope

Eight focused local checks passed on the reviewed copy: six regression tests and two JSON publication tests. Checks cover metadata, hierarchy boundaries, blank required fields, dry-run behavior and template output. Concurrent publication produced one complete file without overwriting an existing result.

Checks use synthetic inputs. Live SQL Server/1C, Windows Excel COM and network-share behavior were not validated. These checks are not production performance benchmarks.
